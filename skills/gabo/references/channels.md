# Channels

Length and shape for hero, CTA, and OG copy, blog posts, LinkedIn, Twitter/X, outreach, and spoken lines. Site routes, blog IA, and package field lengths live in those repos' docs; start at their `AGENTS.md`.

Start from one real, already-verified fact: a shipped feature, a decision made, a problem solved. One source can become several pieces. Rewrite each for its channel.

## Hero, CTA, and OG copy

One job, one verified shipped fact, no borrowed claims, nothing invented to land harder.

## Blog

Open on the concrete situation and keep the argument moving in connected paragraphs. End on the last decision, constraint, or action. Go deeper on implementation than social copy. Spell an acronym out the first time it appears. Every code block gets a sentence in the prose that says what it does.

Post titles are title case. H2 and H3 are sentence case and name what the section contains. `Takeaways`, `Overview`, `Notes`, and `Conclusion` are not headings.

A list stays when each item is a concrete part. Introduce a list with a colon. A bold label is fine when the words after it say what the part does.

## LinkedIn and Twitter/X

The usual brief is a link to the piece. Open that piece.

Hand back the piece's hero image, then one paragraph of one or two connected sentences built on one verified fact from the piece, then the link. State that fact plainly. The paragraph and the link together stay under 280 characters, so the same text works on X. Name the image beside the text so it can be attached. That image line is part of the draft you hand back, and it sits outside the 280-character count. When a short link came with the brief, the link line is that short link. A piece URL on its own is the link line.
